# TeaMall V2.0 第七阶段验收报告

> 验收基准：develop 分支，第七阶段全部小阶段（V2.0-7.1 ~ V2.0-7.6）叠加于第六阶段基线之上

## 1. 后端 API 测试

- 审计现有测试体系：pytest（`backend/tests/` 35 个既有文件 + 本阶段新增 3 个文件），`conftest.py` 强制测试环境（`tea_mall_test` 3307 + Redis DB15），Alembic 迁移建表（0001–0008），会话级数据与上传文件清理，破坏性操作有 `ensure_testing_environment` 环境保护。
- 按提示词 17 项范围（用户 / 商品 / 权限 / 缓存）建立覆盖矩阵：全部已有对应测试，无生产功能缺口；本阶段仅补齐认证安全与商品缓存两个方向共 4 个缺口用例（详见第 6/7 节）。
- 基线 303 passed → 最终 312 passed，0 failed；测试可重复执行，数据完全隔离，不依赖开发库与既有测试数据。

## 2. 认证与权限测试

- 提示词 10 项重点逐项核对：未登录 401、普通用户 Admin/商品/SKU/库存/上下架 403、DISABLED 旧 Token 拒绝、Admin 正常、Logout 后 Refresh 失效、过期 Access 正常 Refresh，均有关键证据（test_auth / test_token_lifecycle / test_user_status / test_jwt_security / test_phase5_integration / test_admin_users 等）。
- 安全要求确认：权限由后端最终判断（全部用例直连 API，绕过前端）；用户不可自改 role（`UpdateProfileRequest` 为 `extra=forbid`）；注册携带 `role=admin` 被忽略、账号仍为普通用户、Admin 接口 403；错误响应不泄露密码/Token/Secret。
- 定向测试 94 passed（92 既有 + 2 新增）。

## 3. 商品与 Redis 测试

- 商品范围：创建/查询/详情/SKU/不同 SKU 价格与库存/分类/搜索/上下架全覆盖；商品→SKU→价格→库存关系显式验证（含新增多 SKU 独立价格库存用例）。
- Redis 范围：首次查询 Miss→MySQL→Redis、二次 Hit（零 SQL）、缓存过期重建、写后失效（改名/改价/SKU/分类/上下架/图片/订单扣库存与恢复）无"MySQL 新、Redis 旧、API 返回旧"。
- 故障降级三层语义：商品/分类缓存 fail-open（故障时回退 MySQL 仍 200）；认证链路 fail-closed（登录/Refresh/Logout 故障时 503，不放行失效令牌）；限流 fail-open。新增 Logout 故障语义用例锁定该行为。
- 定向测试 94 passed（92 既有 + 2 新增）。

## 4. 前后端联调

- 前端静态审查：`http.ts` Token 注入、401 单飞刷新、`ACCOUNT_DISABLED` 强制登出；`api/auth.ts` refresh/logout 走裸 axios 避免重放循环；`store/auth.ts` 双 Token 持久化；路由守卫 `requiresAuth` / `requiresAdmin` 齐全。
- 真实 HTTP 联调（临时 uvicorn 18000 + `tea_mall_test` + Redis DB15）：**38/38 通过**，覆盖四条流程（注册→登录→用户→登出；登录→列表→搜索→分类筛选→详情；Admin→商品/SKU/库存/上下架；普通用户浏览→直连 Admin API 403），另含 Refresh 轮换与登出撤销。
- 前端 `npm run build`（vue-tsc + vite）通过，仅既有主 chunk 体积警告；前后端契约未变，无需修改生产代码。

## 5. 并发与回归测试

- 新增 `test_basic_concurrency.py`（仅 ThreadPoolExecutor，无新依赖）5 场景全部通过：并发商品列表、并发商品详情、并发缓存 Miss 同一商品（回源 MySQL 后重建缓存）、并发登录（不同用户）、并发 Admin 只读 API。
- 未实现订单库存锁定/扣减/回滚（明确留待后续订单阶段）。
- 全量回归：pytest **312 passed**、`npm run build` 通过，认证/RBAC/用户状态/商品/SKU/分类/搜索/Redis/缓存失效均无破坏。
