# TeaMall V2.0 第一大阶段验收报告

> 验收日期：2026-08-14
> 验收基准：develop 分支，未提交的工作区改动（1.1～1.6 全部小阶段）

## 一、第一阶段目标

将 V1 项目升级到「安全、稳定、可重复启动、测试隔离、适合多人协作」的 V2.0 基础状态：

- 安全：JWT Secret 不泄露、无默认弱 Secret、无固定管理员弱密码、非法 JWT/异常输入不产生 500、敏感配置不进 Git、测试不连生产/开发环境。
- 稳定：Docker 冷启动成功、健康检查准确、MySQL 未就绪不随机失败、正常错误不变成 500。
- 测试：pytest 使用独立测试数据库与 Redis，破坏性操作有环境保护，关键安全点有回归测试。

## 二、各小阶段完成内容

### V2.0-1.1 安全配置与 JWT Secret

- `JWT_SECRET` 改为必填且无默认值；缺失、<32 字节、命中历史弱值（`dev-only-*`、`change-me-*`）时拒绝启动。
- `docker-compose.yml` 删除 JWT/MySQL/DATABASE_URL 的不安全默认值，改为 `${VAR:?}` 强制要求。
- 根目录与 backend 的 `.env.example` 全部改为占位符，不再包含真实口令。
- `database/init.sql` 删除硬编码 `tea_mall_dev` 建用户语句，改由容器环境变量创建。
- README 与部署文档补充 JWT 生成、拒绝启动行为说明。
- 新增 12 个安全配置/JWT 回归测试；本地 `.env` 已生成随机 64 字符 Secret。

### V2.0-1.2 管理员账号与密码安全

- `seed.py` 管理员用户名/密码改为从 `ADMIN_USERNAME`/`ADMIN_PASSWORD` 环境变量读取；缺失、<12 位、超 72 字节、命中弱密码名单（含 `admin123`）时拒绝执行；不再打印明文密码。
- 保持幂等（已存在跳过）；新增 `--reset-admin-password` 重置路径。
- README 明确「首次初始化 / 重复幂等 / 重置密码」流程。
- 新增 9 个回归测试，并完成容器内真实 seed CLI 冒烟验证。

### V2.0-1.3 JWT 异常与认证安全

- `decode_access_token` 要求 `sub` 与 `exp` 必须存在。
- `sub` 严格校验（正整数或数字字符串），object/list/布尔/负数/非数字一律判无效；`get_current_user` 全路径捕获异常统一 401，`get_optional_current_user` 降级为 None；401 响应不泄露 token/payload/堆栈。
- 新增 17 个 JWT 异常测试并扩充 auth 测试；真实 HTTP 实测 10 种非法 token 全部 401 无 500。

### V2.0-1.4 密码与用户输入安全（含库存并发）

- 注册/登录密码按 UTF-8 字节校验（≤72 字节），超长返回 422；空/缺失/非字符串 422。
- bcrypt 层增加字节防御，服务层捕获异常转 400，bcrypt 异常不再产生 500。
- 下单改为事务内 `SELECT ... FOR UPDATE`（按商品 id 排序加锁）防并发超卖。
- 新增 16 个密码/并发测试（真实 MySQL 下 5 轮并发验证一单一成、库存归 0）。

### V2.0-1.5 Docker 冷启动与 Healthcheck

- MySQL healthcheck 改为 TCP（`mysqladmin ping -h 127.0.0.1 --protocol=tcp`），Redis healthcheck 显式 `-h 127.0.0.1`。
- 后端启动建表增加有限重试（20 次 × 2 秒，约 40 秒），耗尽后明确报错退出，不靠无限重启掩盖。
- 图片上传限制 10MB（后端流式限流 413 + 清理半成品；nginx `client_max_body_size 10m`）。
- `requirements.txt` 全部依赖精确锁定版本。
- 完成三轮冷启动/重启验证（全新卷 + 两次 down/up），四服务健康、接口正常。

### V2.0-1.6 测试数据库与 Redis 隔离

- `config.py` 新增 `testing` 标识与 `ensure_testing_environment()`（校验 TESTING、数据库名 `tea_mall_test`、Redis DB 15）。
- `cache.clear_all()` 非测试环境直接拒绝执行。
- `conftest.py` 在导入 app 前强制设置测试环境；破坏性清理前环境保护；显式注册 `get_db` dependency_overrides。
- `database/init.sql`、`sql/init.sql` 新增 `tea_mall_test` 建库与授权（新数据卷自动创建）。
- 新增 7 个隔离保护测试。

## 五、安全检查结果

- 无真实 Secret 进入 Git：`.env`/`backend/.env` 均被 `.gitignore` 忽略且从未被跟踪；`.env.example` 仅含占位符。
- 无固定管理员弱密码：seed 拒绝 `admin123` 等弱值；仓库中相关字样仅为黑名单、文档提示与测试固定值。
- 非法 JWT 全部返回 401、无 500；超长/异常密码全部 4xx、无 500（回归测试覆盖）。
- docker-compose 无公开默认 Secret；缺失或弱值 JWT_SECRET 时后端拒绝启动（实测）。
- 关键词扫描：无 TODO/FIXME 残留；`admin123`/`password123` 命中均为黑名单或测试环境固定值。

## 六、遗留问题

- 前端主 chunk 约 1.1MB，构建仅有体积警告（非错误），后续可做路由级代码分割。
- 测试用例中的普通用户密码固定为 `password123`（仅测试环境使用）。
- 本地 Windows MySQL（3306）与容器 MySQL（3307）并存，运行测试需显式指向测试库（README 已说明）。

## 七、未解决风险

- MySQL/Redis 端口对宿主机开放且无认证（dev-only 设计，生产部署需另行加固）。
- 无 CI（仓库无 `.github/`），回归依赖人工执行 pytest。
- 无数据库迁移工具（使用 `create_all`），后续 schema 变更需人工处理或引入 Alembic。
- 无 Redis 服务的主机上，pytest 缓存调用会退化为慢连接（本项目验收环境使用容器 Redis，无影响）。
