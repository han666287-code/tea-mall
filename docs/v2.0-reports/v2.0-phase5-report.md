# TeaMall V2.0 第五阶段验收报告

> 验收日期：2026-08-15
> 验收基准：develop 分支，未提交的工作区改动（V2.0-5.1 ~ V2.0-5.5 全部小阶段）

## 1. 认证体系整合

- 审计确认：JWT 编解码仅存在于 `backend/app/core/security.py`（HS256，claims 仅 `sub/type/jti/ver/iat/exp`），认证依赖仅存在于 `backend/app/core/deps.py`（`get_current_user` / `get_optional_current_user` / `get_current_admin` / 新增 `get_optional_current_admin`），全仓库无第二套 Token 验证逻辑。
- 认证面清晰：公开端点（register、login、refresh、商品列表/详情、分类列表、health）无需登录；购物车、订单、个人资料、改密、登出统一 `get_current_user`；商品/分类写操作与 Admin 接口统一 `get_current_admin`。
- Refresh Token 生命周期符合第三阶段设计：Redis 存 SHA-256 指纹、TTL 7 天、轮换即删、epoch 校验、logout 撤销 Access（黑名单）+ Refresh。
- Redis Token 管理统一：`token_store` 独占 `auth:refresh:*` / `auth:epoch:*` / `auth:blacklist:*`，全部带 TTL，故障 fail-closed（503）。

## 2. RBAC 与商品业务整合

- 新增集中式可选管理员依赖 `get_optional_current_admin`（基于 `get_optional_current_user`，未登录/普通用户/禁用用户返回 None），`backend/app/routers/products.py` 列表/详情读接口改用该依赖，移除 router 内联 `role == "admin"` 判断；服务层守卫（403 `ADMIN_PERMISSION_REQUIRED`、下架商品对非 Admin 404）保留为纵深防御。
- 权限矩阵测试（新增 `backend/tests/test_phase5_integration.py`）：未登录 401 / 普通用户 403 / Admin 成功 × 商品查询（含 include_off_sale 与下架详情隐藏）、新增、修改、SKU 替换、库存修改、上下架；普通用户直连 Admin 写接口无法绕过。

## 3. 用户状态联动

- 状态链路确认：登录 403 `ACCOUNT_DISABLED`、认证 401、可选认证视为游客、Refresh 401；Admin 禁用用户时 epoch+1，全部旧 Token 立即失效。
- 补充业务端点用例：DISABLED 普通用户旧 Token 访问购物车/订单/商品写接口全部被拒；DISABLED Admin 旧 Token 访问 Admin 接口被拒；直改库禁用（不 bump epoch）旧 Token 在业务端点仍按 401 `ACCOUNT_DISABLED` 拦截，验证"Token 合法 ≠ 用户仍有权限"。
- 前端 `http.ts` 已处理 401 `ACCOUNT_DISABLED`（强制登出 + 提示"账号已被禁用"），无需修改。

## 4. 敏感接口保护

- 新增 `backend/app/services/rate_limit.py`：Redis 固定窗口计数器（键前缀 `auth:rate:`），首次 `SET NX EX` 建键并带 TTL，窗口过期自动恢复、键不无限积累；超限返回 429 `RATE_LIMITED`，文案为通用提示，不泄露认证信息；Redis 故障 fail-open（记录日志放行），不误伤正常用户。
- 仅保护登录接口（按确认范围）：`POST /api/auth/login` 先按 IP（`X-Forwarded-For` 首值，否则直连地址）、再按用户名计数。
- 默认阈值：窗口 300 秒、IP 30 次、用户名 10 次（`LOGIN_RATE_LIMIT_*` 可选配置，0/负数关闭对应维度）。
- refresh/改密/Admin 敏感操作已审计，当前不额外限流（记录为后续可选项）。

## 5. 前后端联调

- 真实 HTTP 联调（临时 uvicorn + tea_mall_test + Redis DB15）：**32/32 通过**，覆盖 注册 → 登录 → 刷新（轮换/旧 refresh 拒绝）→ 登出（Access 失效）→ 商品浏览/详情 → 管理端分类/商品/库存/SKU/上下架 → 加购 → 下单 → 用户取消（恢复库存）→ 再下单 → 支付 → 管理员取消已支付订单 → 普通用户越权 403 → 禁用用户旧 Token 401。
- 前端链路验证：`http.ts` Token 注入与 401 单飞刷新、`store/auth.ts` 双 Token 持久化、路由守卫（requiresAuth/requiresAdmin）、管理端页面仅 Admin 可达；`npm run build` 通过，API 契约未变，前端零改动。

## 6. API 变化

- 新增错误码：`RATE_LIMITED`（429，detail 为通用文案）。
- 新增可选配置：`LOGIN_RATE_LIMIT_WINDOW_SECONDS` / `LOGIN_RATE_LIMIT_MAX_PER_IP` / `LOGIN_RATE_LIMIT_MAX_PER_USER`（默认 300 / 30 / 10，缺省不破坏启动）。
- 内部新增依赖：`get_optional_current_admin`（非公共 API）。
- 无新增接口、无数据库迁移、无破坏性请求/响应结构变更；`POST /api/auth/login` 增加限流检查但不改变请求/响应格式。

## 7. 前端变化

- 本阶段前端无代码改动；429 错误由 `http.ts` 通用错误分支展示后端 detail，不触发 401 刷新逻辑；`ACCOUNT_DISABLED` 强制登出逻辑为既有实现。
- 前端构建（vue-tsc + vite）通过，仅既有主 chunk 体积警告。
