# TeaMall V2.0 第四阶段验收报告

> 验收日期：2026-08-15
> 验收基准：develop 分支，未提交的工作区改动（V2.0-4.1 ~ V2.0-4.4 全部小阶段）

## 1. 商品/SKU体系

- 商品模型升级为「商品 → SKU → 规格/规格值」结构，新增 `product_specs`、`product_spec_values`、`skus`、`sku_spec_values` 四张表；SKU 独立决定价格与库存
- 同一商品所有 SKU 共用同一组规格名，每个 SKU 每个规格取一个值，组合通过 `spec_signature` 唯一约束防重复；支持单规格（净含量 100g/200g/500g）与多规格（净含量 × 包装）
- 存量商品迁移自动回填默认 SKU（`DEFAULT-{id}`，价格/库存取自原商品），数据零删除零回填；商品级 `price/stock` 保留为"启用 SKU 最低价/库存之和"汇总字段，由服务层自动维护
- 校验规则：规格名一致性、单 SKU 规格名不重复、组合唯一、sku_code 唯一、商品至少保留 1 个 SKU、价格库存非负
- 前端：详情页规格选择器（价格/库存/可购数量跟随选中 SKU），卡片单 SKU 直接加购/多 SKU 进详情选规格，管理端内嵌 SKU 编辑器（规格值组合 + 编码/价格/库存/启停 + 增删行）

## 2. 库存与上下架

- 库存以 SKU 为核心：`cart_items.sku_id`（唯一约束 user_id+sku_id，同 SKU 累加、不同 SKU 分行，SKU 删除级联清空购物车行）、`order_items.sku_id`（可空，SKU 删除置 NULL，历史快照保留）
- 购买校验顺序：SKU 存在（404 `SKU_NOT_FOUND`）→ 商品上架（400 `PRODUCT_OFF_SALE`）→ SKU 启用（400 `SKU_DISABLED`）→ 数量 ≤ SKU 库存（400 `INSUFFICIENT_STOCK`）
- 下单：锁定 SKU 行（FOR UPDATE 按 id 排序防死锁），价格取 `sku.price`，扣 `sku.stock`，同一事务内重算商品汇总并清购物车；取消订单按 sku_id 恢复 SKU 库存（SKU 已删则跳过）
- 商品上下架沿用 `products.is_on_sale` 总开关 + SKU `is_active` 启停；下架商品不能加购/下单
- 权限：SKU 写入、库存修改、上下架全部复用第三阶段 RBAC（`get_current_admin`），普通用户一律 401/403，未重新设计权限系统

## 3. 分类、图片与搜索

- 分类：复用现有单级分类实现（创建/查询/商品关联/删除保护），未改动结构，回归测试通过
- 图片：新增 `product_images` 表（kind 区分 main/detail + sort_order，存量主图自动回填）；`POST /products/{id}/image` 主图上传（同步 `image_url` 与 main 行，重复上传替换）；新增 `POST /products/{id}/images` 详情图多图上传、`DELETE /products/{id}/images` 详情图删除（清理 uploads 文件）；前端详情页画廊 + 管理端多图管理
- 搜索：复用现有 MySQL LIKE（name/description）+ category_id + include_off_sale（仅管理员），未引入 ES，补关键词+分类、关键词+下架、分类+下架组合测试

## 5. API变化

新增接口：
- `PUT /api/products/{id}/skus`（管理员批量替换 SKU）
- `POST /api/products/{id}/images`（管理员详情图多图上传）
- `DELETE /api/products/{id}/images`（管理员按 url 删除详情图）

变更接口：
- `ProductResponse` 增加 `skus`、`images`；`ProductCreate/Update` 支持可选 `skus`
- `CartItemCreate` 由 `product_id` 改为 `sku_id`；`CartItemResponse` 增加 `sku`
- `OrderItemResponse` 增加 `sku_id`
- `products.price/stock` 语义变为启用 SKU 汇总（最低价/库存之和）

新增错误码：`SKU_NOT_FOUND`、`SKU_CODE_TAKEN`、`SKU_DUPLICATE_SPECS`、`SKU_INVALID_SPECS`、`SKU_DISABLED`、`PRODUCT_NEEDS_SKU`、`PRODUCT_HAS_SKUS`、`PRODUCT_IMAGE_NOT_FOUND`

## 8. 遗留问题

- 无 CI：仓库无 GitHub Actions，回归依赖人工执行 pytest
- 前端主 chunk 约 1.1MB 构建体积警告（非错误，可做路由级代码分割）
- 管理员批量替换 SKU 等于删除旧 SKU 行，引用它的购物车行会被级联清空（设计行为，需在管理端操作时注意）
- 有订单历史的商品删除仍返回 409（既有行为）
- 本机 MySQL（3306）与 Docker MySQL（3307）并存：运行中的 Docker 后端使用 3307，`backend/.env` 已统一指向 3307；DataGrip 查看请连接 `127.0.0.1:3307`
