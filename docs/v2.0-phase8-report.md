# TeaMall V2.0 第八阶段验收报告

> 验收日期：2026-08-16
> 验收基准：develop 分支（b1cfafa，第七阶段之上），第八阶段全部小阶段（V2.0-8.1 ~ V2.0-8.5）依次验收通过后进入本报告

## 1. 冷启动问题分析

对 README、`.env`/`.env.example`、`.gitignore`、`docker-compose.yml`、前后端 Dockerfile、entrypoint、Alembic、数据库初始化脚本、Redis/MySQL 配置、FastAPI/Vue 启动方式做了只读勘查。当前冷启动基础已较完整（README 一键启动、compose healthcheck、entrypoint 自动迁移、nginx 反代均就位），但存在以下问题：

- 阻塞启动：compose 中 backend 依赖 redis `service_healthy`，与 README「Redis 不是硬依赖」及第七阶段 fail-open 设计矛盾，Redis 故障会阻塞整个平台启动。
- 影响功能：`ADMIN_USERNAME/ADMIN_PASSWORD` 未入 `.env.example`；`MYSQL_PASSWORD` 与 `DATABASE_URL` 密码需保持一致（占位符一致但缺少醒目说明）；pytest 默认连接端口与 Docker 映射不一致（文档已覆盖）。
- 文档不完整：`docs/development/roadmap.md` 与 `dependency-tree.md` 仍为 V1 阶段表，未含 V2.0 阶段表（V2.0-1 ~ V2.0-8）；README 缺逐变量环境变量总表；`docs/docker-deployment.md` 启动顺序与 compose 实际配置不一致。

## 2. 环境变量标准化

- 根 `.env.example`：逐项补齐作用/必填/默认值/示例值说明；`JWT_SECRET` 保持空值并给出两种生成命令；`MYSQL_PASSWORD` 与 `DATABASE_URL` 占位符保持一致；新增可选 `ADMIN_USERNAME`（默认 admin）/`ADMIN_PASSWORD`（seed 时必填，至少 12 位）说明；写明 Docker 内连接串 host 用服务名 `mysql`/`redis`、本地开发用 `localhost`。
- `backend/.env.example`：同步同样的说明，并注明 Docker 部署时本文件不生效（环境变量由根 `.env` + compose 注入）。
- README 新增「环境变量说明」总表（16 行，覆盖全部变量），并说明根 `.env` 与 `backend/.env` 的适用场景。
- `.gitignore` 复核：`.env`、`.env.*`、`!.env.example`、`node_modules`、`dist`、`backend/uploads/`、`.venv`、日志均已覆盖，无需修改。
- 检查结论：`config.py` 与 `sql/init.sql` 中的 `tea_mall_dev` 为公开开发默认值（README 已说明），不修改；未新增 `DB_HOST`/`VITE_*` 等拆分变量。
- 验证：`docker compose config` 通过；全新目录按 `.env.example` 复制并填入 JWT_SECRET 后 `docker compose config` 通过（15 个变量全部正确解析）；后端导入冒烟通过；跟踪文件敏感扫描无真实密码/Secret（仅占位符与测试固定值）。

## 3. Docker Compose

- `docker-compose.yml`：backend `depends_on` 中 mysql 保持 `service_healthy`（迁移与业务强依赖数据库）；redis 由 `service_healthy` 改为 `service_started`（只等容器启动，不阻塞后端），并保留 redis healthcheck 供 `docker compose ps` 观察。
- 四服务（frontend/backend/mysql/redis）其余配置复核达标：MySQL 持久化 + `database/init.sql` 初始化 + healthcheck；Redis 持久化（AOF）+ healthcheck；backend 先 `alembic upgrade head` 再启动 uvicorn + 自身健康检查；frontend 多阶段构建 + nginx 反代 `/api`、`/uploads`。
- `frontend/.dockerignore` 增加 `.env*` 防护。
- `docs/docker-deployment.md` 启动顺序同步更新（backend 只等 mysql healthy，Redis 不阻塞启动）。
- 验证：`docker compose up -d --build` 全部 healthy；`docker compose stop redis` 后 backend 保持 healthy、前端不掉线、商品列表仍 200（回退 MySQL）、`/api/health` 仍 HTTP 200（redis=false）；`docker compose start redis` 后恢复。

## 4. MySQL

- 容器 `mysql:8.0`：数据卷 `mysql-data` 持久化；`MYSQL_DATABASE`/`MYSQL_USER`/`MYSQL_PASSWORD` 环境变量初始化；挂载 `database/init.sql`（幂等，创建 `tea_mall` 与 `tea_mall_test` 并授权）；healthcheck 为 `mysqladmin ping`。
- 验收实测：`mysqladmin ping` → `mysqld is alive`；数据库列表含 `tea_mall`、`tea_mall_test`；`tea_mall` 12 张表；Alembic 版本 `0008`（0001–0008 全部应用）。

## 5. Redis

- 容器 `redis:8-alpine`：数据卷 `redis-data` + AOF 持久化；healthcheck 为 `redis-cli ping`。
- 验收实测：`redis-cli ping` → `PONG`；冷启动全新 volume 下商品/分类缓存可写入与命中。
- 降级语义（与第五、六、七阶段设计一致）：商品/分类缓存 fail-open（Redis 故障回退 MySQL 仍 200）；认证链路 fail-closed（故障时 503，不放行失效 Token）；`/api/health` 如实反映 Redis 状态。

## 6. Backend

- 镜像 `python:3.13-slim`，安装 `requirements.txt` 全部依赖；入口 `docker-entrypoint.sh` 先有限重试 `alembic upgrade head`（20 次 × 2s）再启动 uvicorn；环境变量全部来自 compose 注入（根 `.env`），无硬编码秘密。
- 验收实测：冷启动环境 backend 自动完成迁移并 healthy；`/api/health` ok（db/redis true）；注册/登录/Refresh/登出、商品列表/详情/搜索、Admin 登录与商品管理、越权 403 全部通过；pytest 全量 312 passed。

## 7. Frontend

- 镜像 `node:20-alpine` 构建（`npm ci` + `npm run build`）→ `nginx:1.27-alpine` 托管；`nginx.conf` SPA history 回退 + `/api`、`/uploads` 反代 backend。
- 验收实测：前端 8080/18080 可打开；经 nginx 的 `/api/health` 与 `/uploads/...` 图片访问正常；宿主 `npm run build`（vue-tsc + vite）通过，仅既有 chunk 体积警告。
