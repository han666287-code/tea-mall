# TeaMall V2.0 第二大阶段验收报告

> 验收日期：2026-08-14
> 验收基准：develop 分支，未提交的工作区改动（V2.0-2.1 ~ V2.0-2.6 全部小阶段）

## 一、第二阶段目标

将后端从"功能可用"提升到"数据库与后端工程化"，重点解决：数据库版本管理、Session/Transaction 管理、统一异常处理、API Response 规范、Request/Response Schema、Router/Service/Repository 职责、数据库约束、索引、SQL 查询质量、N+1、分页与回归测试。

## 二、各小阶段完成内容

### V2.0-2.1 Alembic 数据库迁移体系

- 新增 `alembic==1.14.0` 依赖与 `alembic.ini`、`alembic/env.py`、`script.py.mako`、`versions/0001_initial_tables.py`；空库可通过迁移完整建出 6 张表，支持 `current/history/upgrade/downgrade`。
- 移除应用启动 `create_all`（`main.py`）；Docker 入口 `docker-entrypoint.sh` 先执行 `alembic upgrade head` 再启动 uvicorn；测试基座 `conftest.py` 改用迁移建表。
- 存量库收养：3306/3307 的 `tea_mall` 执行 `stamp head`，数据零改动。

### V2.0-2.2 数据库事务与 Session 管理

- `get_db` 改为"业务显式 commit、未处理异常统一 rollback、finally close"；清理 6 处冗余 `db.refresh`（仅创建类保留）；`seed.py` 增加异常回滚。
- 审计确认 15 个写路径均单次 commit；下单 FOR UPDATE 防超卖事务保持。

### V2.0-2.3 统一异常处理体系

- 新增 `BusinessException` 与 5 个统一异常处理器：业务异常 4xx、HTTPException `http_<status>`、校验错误 422 `validation_error`、IntegrityError 409 `integrity_error`、未知异常 500 `internal_error`；错误体统一为 `{detail, code}`，响应不泄露 traceback/路径/密钥。
- 服务层 16 处 `HTTPException` 替换为带稳定错误码的业务异常；修复 Pydantic 校验错误 `ctx` 中 `ValueError` 无法 JSON 序列化的真实 Bug。

### V2.0-2.4 统一 API Response 与 Schema / DTO

- 新增 `schemas/common.py`：`MAX_PAGE_SIZE=50` 常量与泛型 `PageResponse[T]`；`ProductListResponse`、`OrderListResponse` 统一继承；成功响应结构零变化。
- 新增契约测试：9 个响应模型字段与前端 TS 类型逐一对应、递归断言无 `password/password_hash` 泄露、分页键与上限校验。

### V2.0-2.5 Router / Service / Repository 分层治理

- 仅 Product/Order 建立轻量 Repository（`product_repository.py`、`order_repository.py`），只放查询不放业务规则；cart/order/admin/category 服务复用。
- 新增 `services/category.py`、`services/product.py`；categories/products router 分别瘦身 57/136 行；图片上传校验、10MB 流式限制与半成品清理移入服务层。
- 分层重构后路径、状态码、错误文案、缓存键与失效时机逐项保持不变。

### V2.0-2.6 数据库约束、索引与查询优化

- 迁移 `0002`：`order_items.product_id` 索引 + 5 个 CHECK 约束（库存/价格 ≥ 0、购物车/订单明细数量 ≥ 1、订单金额 ≥ 0）；downgrade 正确处理 MySQL 1553（先删外键再删索引再重建）。
- N+1 修复：商品列表 `selectinload(category)`、购物车 `selectinload(product→category)`、订单列表/详情/管理端 `selectinload(items)+joinedload(user)`。
- 存量库 3306 与容器库均升级至 0002；数据审计零违规（MySQL 8.0.45/8.0.46 强制 CHECK）。

## 五、API 变化与 Breaking Changes

- 错误响应体新增 `code` 字段（`detail` 保留）：`http_<status>`、业务码（`USERNAME_TAKEN` 等）、`validation_error`、`integrity_error`、`internal_error`。
- 422 校验错误新增 `code`，`detail` 仍为原始校验数组。
- 分类/商品路由错误码由 `http_400/http_404/http_403` 升级为稳定业务码（`CATEGORY_NAME_TAKEN`、`CATEGORY_NOT_FOUND`、`PRODUCT_CATEGORY_NOT_FOUND`、`ADMIN_PERMISSION_REQUIRED` 等）。
- 成功响应结构、状态码、错误 `detail` 文案均无变化，前端兼容，零改动。
